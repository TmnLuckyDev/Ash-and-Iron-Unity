# 01. Installation og Quantum-konfiguration

## Versionsbeslutning

Officielt tilgængelig 24.11.2026: **Quantum 3.1.0 Stable Build 2313**, udgivet 16.11.2026. Unity **6.3 LTS (6000.3)** er fuldt understøttet og har LTS-support til december 2027. Brug seneste 6000.3-patch der er tilgængelig i Hub, og registrér det eksakte patchnummer i `ProjectSettings/ProjectVersion.txt` efter installation. Unity 6.0 har udløbet ordinær LTS-support, og 6.7 LTS er endnu ikke udgivet. Quantum 3.1 har ændret kommando-API til `AddCommand`, gammelt `SendCommand` er deprecated. [Quantum SDK](https://doc.photonengine.com/quantum/v3/getting-started/initial-setup) · [Unity LTS](https://unity.com/releases/unity-6/support) · [3.1 migration](https://doc.photonengine.com/quantum/v3/getting-started/migration-guide/migration-guide-3.1).

## Editor og SDK, trin for trin

1. Download [Unity Hub](https://unity.com/download). Log ind på din egen Unity-konto og aktivér en licens, du er berettiget til. Der foretages ingen køb.
2. Hub → Installs → Install Editor → Official releases → Unity 6.3 LTS. Vælg den seneste patch. Ved en eksisterende Hub-installation bruges tandhjul/tre prikker → Add Modules.
3. Tilføj Android Build Support inklusive Android SDK & NDK Tools samt OpenJDK. Brug de versioner, som følger med editoren. Unity dokumenterer [Android setup](https://docs.unity3d.com/6000.3/Documentation/Manual/android-sdksetup.html).
4. Tilføj iOS Build Support og Web Build Support (WebGL). Installér også Windows/Mac build support hvis to desktop-klienter skal testes. iOS eksporteres som Xcode-projekt og færdigbygges på macOS. [iOS setup](https://docs.unity3d.com/6000.3/Documentation/Manual/ios-environment-setup.html).
5. Hub → Projects → New project → Universal 3D (URP). Navn `AshAndIronUnity`. Vælg **en separat mappe**, aldrig fantasy-rts' eksisterende rod. URP er velegnet til styliseret 3D, instancing, enkle skygger og separate kvalitetsprofiler. Unity skal stå for visningen, Quantums egen ECS for gameplay. Unity DOTS er ikke påkrævet.
6. Edit → Project Settings → Player. Angiv produktnavn og særskilt test-bundle-ID, fx `com.ashandiron.unitytest`; bevar den nuværende Capacitor-app på `com.ashandiron.game`. Under Resolution and Presentation vælges Portrait. Landscape kan tilføjes senere med responsive layouts. Brug uGUI (`com.unity.ugui`) til prototypen; kontrollér at pakken findes i Window → Package Manager. Aktivér synlige `.meta`-filer og tekstserialisering af Unity assets. Commit `.meta`, ProjectSettings og Packages manifest/lock; ignorér Library, Temp, Logs, Builds, lokale credentials, signing-filer og IDE-cache.
7. Åbn [Photon Dashboard](https://dashboard.photonengine.com) og opret en gratis konto med egne oplysninger. Opret under YOUR → APPS → Development → Create a new app. Vælg Quantum og Quantum 3 som SDK, navn `AshAndIron-Unity-Dev`. Kopiér app-ID'et. Opret ikke et abonnement. For lokalafprøvning kan ID springes over.
8. Hent `Quantum 3.1.0 Stable Build 2313` som Unitypackage fra [SDK Download](https://doc.photonengine.com/quantum/v3/getting-started/initial-setup). Importér via Assets → Import Package → Custom Package. Brug hele pakken; tarball-varianten har en begrænsning omkring debug-DLL-valg, så Unitypackage er valgt til prototypen.
9. Efter import åbner Quantum Hub. Ellers Tools → Quantum → Quantum Hub. Vælg Install Quantum User Files og behold de installerede assets og assembly definitions. Asteroids kan installeres i en særskilt prøvefolder for en kendt fungerende baseline. Installer multiplayer-menuen eller brug SDK's start-UI nedenfor. [Officiel guide](https://doc.photonengine.com/quantum/v3/video-tutorials/beginner-guide).
10. Indsæt App ID i Hub eller vælg `PhotonServerSettings.asset` i Project-panelet og feltet `AppSettings > App Id Quantum` i Inspector. Skriv ikke ID eller andre Photon-credentials i et offentligt dokument eller repository. [App ID guide](https://doc.photonengine.com/quantum/v3/reference/create-quantum-appid).
11. Behold Photon Cloud Name Server. Region: vælg Europe (`eu`) konsekvent for begge klienter i udvikling, via regionvalg i menu eller Fixed Region i SDK-asset, når feltet er tilgængeligt. I almindelig matchmaking vælges region efter latenstid, og invitationskode skal indeholde match-region. Hold begge klienter på samme AppId og AppVersion. Ingen produktion/Render-konfiguration ændres.
12. I `Assets/QuantumUser/Resources` findes SDK'ets default configs. Duplikér de relevante SimulationConfig, SystemsConfig og SessionConfig assets og giv dem identificerbare Ash & Iron-navne. Brug Inspector-søgning eller Tools → Quantum → Find Config for at finde de præcise assets i importeret version. Lad standardphysics være urørt i SDK-prøvescenen; i RTS-scenen konfigureres kun nødvendige Quantum systems. Navigation/avoidance slås fra, hvis egen gridnavigation anvendes. Mål ThreadCount 1 og SDK-standard separat på enheder. Ingen Unity Rigidbody pr. unit.
13. `SessionConfig` er `DeterministicSessionConfig`. Begge klienter skal bruge samme session asset. Start med `UpdateFPS = 20` for at matche eksisterende spil; 30 er et separat eksperiment efter paritet. Prediction/rollback-vinduer og input delay beholdes først som SDK-default; registrér eksakte værdier. Aktivér periodiske checksums i udvikling (fx hver 60 verified ticks hvis accepteret af config); mål omkostningen og brug ikke checksum-stop som almindeligt anti-cheat-system i release.
14. RuntimeConfig binder map, SimulationConfig, SystemsConfig og seed til den kørende session. Behold SDK's `RuntimeConfig` og udvid den gennem den user partial class, som SDK'et har genereret, med regelsætref, mapref og matchsettings. RuntimePlayer er spillerens startdata; tilføj racedata (enum) og eventuelle godkendte lobbyvalg i den tilsvarende partial class. Stol aldrig på klientens valg af ressourcer, hold, asset eller stats. Brug simulationens PlayerRef fra add-player signalet og tildel deterministisk seat. Ingen signeringsnøgler eller serverhemmeligheder i RuntimeConfig.
15. Åbn standard QuantumGameScene fra User Files. Sørg for Quantum map/scene setup og `QuantumEntityViewUpdater`. Gem som en ny scene `Assets/AshAndIron/Scenes/Prototype.unity`. I Quantum 3.1 kan menuvalget Tools → Quantum → Setup → Add Start UI to the Scene tilføje startdialog (importér TextMesh Pro Essentials hvis det kræves). Brug først eksisterende Scene og SDK default config til baseline. Den officielle guide viser menuen; SDK-hubens sample installation kan være nødvendig.
16. Kopiér pakkens `Assets/QuantumUser/Simulation/AshAndIron` ind i projektet. Kør Tools → Quantum → CodeGen → Run Qtn CodeGen. Tjek `QuantumUser/Simulation/Generated` og `QuantumUser/View/Generated`, Console og C# compiler. Ingen manuel ændring af genererede structs. Kør CodeGen igen efter schemaændring. [DSL](https://doc.photonengine.com/quantum/v3/manual/quantum-ecs/dsl) · [Projektlayout](https://doc.photonengine.com/quantum/v3/manual/quantum-project).
17. Opret to simple prototypes via Hierarchy → Quantum → Empty Entity (eller Quantum → 3D → ønsket entity prototype). Tilføj Transform2D (XZ i 3D, Quantum XY slået fra) og generated `AaiIdentity`, `AaiHealth`, `AaiUnit`, `AaiMovement` til prototypen i Inspector. Tilføj `QuantumEntityView` på separat visuelt prefab eller Self. Brug en simpel model (capsule) uden Unity-fysik til gameplay. Gør prefab til asset. Se [Entity Prototypes](https://doc.photonengine.com/quantum/v3/manual/entity-prototypes). En matchspawner skal oprette ejerskab og health fra de genererede regler i næste fase. Template-prefab alene skaber ikke et fungerende RTS.
18. Import af reference-assets er næste konkrete editoropgave: importer `Reference/data/rules.json` og `maps.json`, konverter navnene til de faste `Aai`-enums fra QTN, opret typed `AaiRulesAsset`/`AaiMapAsset` under Resources/AshAndIron og skriv deterministisk FP via raw values. Kontrollér SHA og alle rækker. Konfigurer scene/RuntimeConfig med de samme assets. Kopiér ikke JSON direkte til runtime som mutable state. Asset-definitionerne er allerede i pakken, men en fungerende importør og faktiske `.asset`-instanser kræver den installerede editor. `AaiRulesAsset` skal suppleres med de resterende serverinvarianter i paritetsfasen.
19. Start editorens Play Mode → Local (eller `QuantumRunnerLocalDebug`). Få SDK-prøvescenen til at køre offline. I RTS-prototypen måles først spawning af de identiske 10 startentities pr. seat og derefter 100/500/1.000. Systemimplementeringen er fase 2. Local Mode har ingen Photon Cloud-forbindelse. Se [Testing](https://doc.photonengine.com/quantum/v3/manual/testing).
20. Online først når lokale prototype-tests består. Tilføj Quantum scene/menu til File → Build Profiles → Scene List. Åbn editor og en separat desktop-build, eller to builds, med forskellige spillere. Samme region/AppVersion/config, 2 players. Test SDK Quick Play/private join og begge clients verified checksums. Quantum 3.1 har optional Quantum-MultiClient pakke, men to OS-processer er bedre til uafhængige målinger. [SDK 3.1 guide](https://doc.photonengine.com/quantum/v3/getting-started/migration-guide/migration-guide-3.1).
21. Android: File → Build Profiles → Add Build Profile → Android → Switch Profile. IL2CPP, ARM64, debug build og fysisk device via USB debugging. Test airplane mode, back, background/resume og online kampe. Udgivelse senere bruger AAB og korrekt signing.
22. iOS: File → Build Profiles → iOS → Switch Profile → Build. Åbn genereret Xcode-projekt på Mac, vælg iPhone-simulator eller fysisk device, konfigurér Apple signing/Developer Mode efter behov. Ingen TestFlight/upload endnu.
23. Web: File → Build Profiles → Web → Switch Profile. Build and Run lokalt. Test browser downloadstørrelse, memory og performance først. Photon understøtter WebGL; Unity 6 kan eksperimentere med web native threading og kræver særskilte host headers til det. Start single-threaded; anvend 3.1 Release SDK og IL2CPP, samt SharpZipLib-pakken hvis kompressions/LTO-problemet opstår. [Quantum WebGL](https://doc.photonengine.com/quantum/v3/manual/webgl) · [Unity browserkompatibilitet](https://docs.unity3d.com/6000.3/Documentation/Manual/webgl-browsercompatibility.html).
24. Begge native testbuilds skal være debug eller development. Gennemfør enhedstest, rollback-test, fysisk mobiltest og benchmark før release-signering. Dokumentér Unity patch, Quantum version, config- og databasehash i hvert artifact. Seed og inputsekvenser skal følge testresultat.

## Gældende begrænsning

Dette miljø har Linux, Node og den tidligere TypeScript-kilde. Hverken Unity Editor, Quantum SDK eller dotnet er tilgængelig. Photon SDK'et kræver downloaderens accepterede licens/adgang. Derfor er ovenstående en praktisk installations- og verifikationsopgave til næste Unity-session og ikke et gennemført CodeGen/build-resultat. Ingen SDK-binarier eller account-token er med i pakken.
